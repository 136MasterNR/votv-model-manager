## What the app is
VotV (Voices of the Void) Model Manager: Bevy 0.16.1 (pinned) desktop app. Browses the printer models folder as icon
tiles with a 3D preview, and converts dropped `.glb` files with the `votv-convert` library (path dependency).
Default folder `%LocalAppData%\VotV\Assets\meshes\printer`. Full feature description: `README.md`.

## How the converter integration works
- Dropping a `.glb` -> `inspect` on a thread (pre-selects Humanoid / Drop transparent) -> every parameter change cancels the
  running job and queues a new `convert_with` on a worker thread (toggles at once, sliders 0.5 s after release).
- Each job builds in a temp folder (`%TEMP%\votv-model-manager-convert\job<N>`), the result is parsed for the preview, then
  installed into the library folder together with `<n>.glb` and `votv_convert.json`. Name rule: see `resolve_name`.
- A cancelled worker must really exit before the next job starts (`workers` counter).
- **`ConvertCache`**: one per converter session in `ConvertState`, a clone is given to each job (`Hooks::with_cache`).
  Cleared when a session starts (`begin_with`) and ends (`end`). The console prints `[convert] reused from cache: ...`.
- Parameters are table-driven: add one `slider(...)` / `toggle(...)` / `choice(...)` row in `conv_ui::rows()`; the `show`
  function hides rows that do not apply.

## UI conventions
- Title-bar button on the right: an **X** that closes the app; on the converter screen it becomes **arrow + "Return"** and
  goes back to the list (`ui::on_close` -> `leave_converter`). There is no separate back button. The button's width is `Auto` with
  padding on the converter screen, so the text always fits.
- Title bar has a **Settings** (gear) drop-down (hidden on the converter screen).
- Icons are glyphs from `assets/fonts/MaterialIcons-Regular.ttf`, compiled into the exe (`icon_font.rs`). Add new ones to `icon_font::g` (`gl('\u{...}')`); only the X has a plain-text fallback, all others are empty if the font is unusable (deliberate: a missing font must be obvious).
- Text that must not wrap uses `line(...)` in `conv_ui.rs`. Children of scrolling boxes use `pass()` or
  `Pickable::IGNORE` so the mouse wheel reaches the scrolling node (`ui::wheel_system` scrolls any hovered
  `Overflow::scroll_y` node).
- The editor title shows file name, triangles, hulls, atlas, warnings (no "saved as").
- Editor = preview + **properties panel** (`conv_ui::build`, a child of `body`, 340 px): icon box + **Regenerate icon**, model name,
  info box, then "Properties" with collapsible sections (`Row::Header` rows; `OpenSections`, a missing entry = CLOSED: all sections start folded). The
  **logs** icon button sits at the preview's bottom left (toggles `conv_ui::LogPanel`; the panel shows the input, a failure
  message, every diagnostic of the last run and the cache stages that were reused). `props_icon_system` shows the saved
  model's `icon.png` and requests one (once per folder) when it is missing.

## Game icon rig (src/gamerig.rs)
Source: the `votv-printer-thumbnails` skill (reverse engineered from `3dPrinterProcessor`; every number there has a [V]/[I]/[?] label).
- **Measured facts (override the skill where they differ):** Unreal (x,y,z) = OBJ (z,x,y); the game's icon background is pure black
  (0,0,0,255), not 0.2 grey (the manager nevertheless renders icons and the preview's icon look on a TRANSPARENT background, user's decision); output is sRGB-encoded; one unit of light intensity adds ~0.342 of albedo (LUX_PER_UNIT 1072);
  the game's texture is sampled sharper than a 128 px downscale (icons now keep up to 1024 px, nearest, no mips).
- Camera FOV 10 deg, 12R from the bounds centre, direction (cos30 cos45, cos30 sin45, sin30) in Unreal axes; two white lights
  at (2R,2R,R) intensity 3 and (-2R,-2R,R) intensity 1, measured from the mesh origin; no ambient, shadows, tone curve or AA;
  background 0.2 grey; 128x128.
- The app uses DIRECTIONAL lights aimed at the centre (the game's point lights have no distance falloff; a Bevy point light
  always has), `Tonemapping::None` and a per-camera `AmbientLight::NONE` (Bevy 0.16 allows `AmbientLight` as a camera component).
- Icon renders now load the diffuse and pbr maps (not only diffuse), so metals come out dark like in the game.
- Preview options: **L** = the game's icon look = the same rules as the icon render (lights, no ambient, no tone curve, transparent background, diffuse + pbr maps only, no normal/emissive, nearest texture sampling, roughness 1 / 0.85; `preview::SectionOrig` remembers the full-detail material so it can be switched off); **G** = the game's icon
  camera (FOV 10, 12R). Both together approximate the game's icon at any size.
- Unit tests for the rig maths are in `gamerig.rs` (`cargo test`, run by the user).

## Gotchas
- Rounded window corners come from `window_style.rs` (DWM, Windows 11 only, FFI without extra crates, finds the window by `WINDOW_TITLE`). Do not try to round the UI itself: Bevy 0.16 does not clip children to `BorderRadius`.
- In `ui::setup` the name `b` is reused for several buttons. Anything that must keep a button (e.g. `close_btn`) needs its own `let` name right at creation, or later `conv_refs.x = b` picks the wrong entity (this is why the Return button never widened).
- Bevy's built-in font is ASCII only; non-ASCII names show as boxes.
- Bevy tuples are limited to 20 systems/bundle items: nest tuples (see `main.rs`).
- Nothing has been verified inside VotV itself unless the user said so (e.g. "no health key = infinite health" was
  observed by the user, not decoded).
- Whether the game accepts an `icon.png` with a transparent background is untested.
